# Sprint 1 Documents

This folder contains requirements and delivery specifications for Sprint 1. Examples illustrate document format; they are not approved Sprint 1 requirements.

## Contents

- [TEMPLATE-BRD.md](./TEMPLATE-BRD.md) — business requirements template; [example](./EXAMPLE-BRD.md).
- [Acceptance criteria template](./acceptance-criteria/EXAMPLE-FEATURE/TEMPLATE-ACCEPTANCE_CRITERIA.md) — story acceptance criteria and sizing; [example](./acceptance-criteria/EXAMPLE-FEATURE/EXAMPLE-ACCEPTANCE_CRITERIA.md).
- [Solutioning template](./solutioning/EXAMPLE-FEATURE/TEMPLATE-SOLUTIONING.md) — API contract; [example](./solutioning/EXAMPLE-FEATURE/EXAMPLE-SOLUTIONING.md).
- [Frontend task template](./task-detail/frontend/TEMPLATE-TASK.md) and [backend task template](./task-detail/backend/TEMPLATE-TASK.md) — task breakdowns; [frontend example](./task-detail/frontend/EXAMPLE-TASK.md) and [backend example](./task-detail/backend/EXAMPLE-TASK.md).
- [Test case template](./test-case/EXAMPLE-FEATURE/TEMPLATE-TC.md) — test scenarios; [example](./test-case/EXAMPLE-FEATURE/EXAMPLE-TC.md).
- [TEMPLATE-GLOSSARY.md](./TEMPLATE-GLOSSARY.md) — glossary template; [example](./EXAMPLE-GLOSSARY.md).

## Guidance

- Copy templates into feature-specific files in this folder or its relevant subfolder. Keep template and example files as references.
- Align each feature's acceptance criteria and solutioning with its approved BRD requirements. Link related documents when feature files are added.
- Mark unresolved details `TBD` and record decisions before treating examples or estimates as commitments.
