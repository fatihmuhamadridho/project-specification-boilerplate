# Project Specification Documents

This repository organizes project requirements, acceptance criteria, and API contracts by sprint. Use templates and examples inside each sprint folder as guidance for that sprint's deliverables.

## Documents

| Document                             | Template                                                                                   | Example                                                                                  | Purpose                                                                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Business Requirements Document (BRD) | [TEMPLATE-BRD.md](./sprint-1/TEMPLATE-BRD.md)                                              | [EXAMPLE-BRD.md](./sprint-1/EXAMPLE-BRD.md)                                              | Describe business context, objectives, scope, requirements, assumptions, plans, and open questions. |
| Acceptance Criteria                  | [Template](./sprint-1/acceptance-criteria/EXAMPLE-FEATURE/TEMPLATE-ACCEPTANCE_CRITERIA.md) | [Example](./sprint-1/acceptance-criteria/EXAMPLE-FEATURE/EXAMPLE-ACCEPTANCE_CRITERIA.md) | Define user stories, verifiable outcomes, technical flow, and estimation details.                   |
| API Contract / Solutioning           | [Template](./sprint-1/solutioning/EXAMPLE-FEATURE/TEMPLATE-SOLUTIONING.md)                 | [Example](./sprint-1/solutioning/EXAMPLE-FEATURE/EXAMPLE-SOLUTIONING.md)                 | Specify API behavior, request and response contracts, validation, and status codes.                 |

## Sprint Documents

The [sprint-1](./sprint-1/README.md) folder contains Sprint 1 documents, a [glossary template](./sprint-1/TEMPLATE-GLOSSARY.md), and a [glossary example](./sprint-1/EXAMPLE-GLOSSARY.md). Create a separate folder for each later sprint and keep its BRD, acceptance criteria, solutioning, and glossary together.

## Usage

- Copy the relevant template inside the sprint folder when creating a sprint document.
- Use the matching example to understand the expected level of detail and format.
- Replace placeholders and examples with confirmed project information.
- Keep unknown details explicit and resolve them with the responsible stakeholders.
